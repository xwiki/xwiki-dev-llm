# KB benchmark

Measures what a version of the `xwiki` plugin — its KB, its hooks, its skills — does for a coding agent,
so a change can be compared with `master` before it is proposed. It is not shipped with the plugin and
not indexed by `kb-search`. Each run is a headless `claude -p`, so it costs API usage: about $0.10 per
group (a)/(b) question with the default Sonnet, more for a group (c) task, plus the Opus judge.

## Layout

- `questions/a.json` — group (a): 40 questions on what the KB covers, generated by Opus
  (`tools/gen-a.mjs`) from `a-sections.json`, a seeded sample of KB `##` sections stratified by file
  count (`tools/sample-sections.mjs`), avoiding each section's key terms. Gold = the section
  (`gold.file` + `gold.section`); `gold.reference`, when present, replaces it as the judge's reference.
  `a-sections.json` freezes each section's text as it was sampled: the judge's default reference.
- `questions/b.json` — group (b): 30 real questions, verbatim, from solved `dev`/`discuss` topics of
  forum.xwiki.org (`tools/fetch-forum.py`), curated by Opus for durable, developer-relevant answers
  (`tools/gen-b.mjs`). Gold = the distilled accepted post, with its URL.
- `questions/c.json` — group (c): 20 real development tasks. Each has a `task` prompt, a `repo` (default
  `xwiki-platform`), the `base` commit to start from, a `cwd` inside the repo, `gold.checklist` (the
  rules the diff, commit messages or final message must respect) and `source` (the real fix, which
  the session must not reach).
- `questions/d.json` — group (d): 10 questions the KB does not answer. No gold: any KB pointer or read is
  noise.
- `tools/` — `run.mjs` (sessions), `judge.mjs` (grading and scoreboard), `recall.mjs` (retrieval only,
  no LLM), `grade-det.mjs` (the group (c) points a diff settles mechanically), `task-repo.mjs` (group
  (c) isolation), `review-pack.mjs` (a human review and blind judge-calibration pack), and the
  generators above.

Everything a run writes goes under the output directory — `--out`, by default `xwiki-dev-llm/eval`
in the plugin's work directory, never the repo: `runs/<label>/<id>.json` (one record per question:
answer, tokens, cost, tool calls, KB files touched, hook pointers, `grade`) with `_scoreboard.json`,
`recall/<label>.json`, `repo-stub/`, `task-repos/` and `clones/`.

## Isolation

Each session is `claude -p` with `--setting-sources ""` (no user settings, so no installed marketplace
plugins), `--strict-mcp-config` (no MCP), `--plugin-dir` (only the plugin under test), the web closed
(`WebFetch`, `WebSearch`, `curl`, `wget`, `gh`, `mvn` and git network commands disallowed) and the
questions and results unreadable: the score must measure the knowledge base, not a live fetch of
xwiki.org nor the gold.

Groups (a), (b) and (d) run in `repo-stub/`, a git repo with an `xwiki/xwiki-platform` origin and a
stub `pom.xml` (18.10.0-SNAPSHOT), so the plugin's scoped hooks fire. Group (c) runs each task in its
own throwaway repo (`tools/task-repo.mjs`): a fresh `git init` that fetches only the task's `base` from
the clone, checked out detached, with no branch, tag, remote ref or object beyond `base` — the real fix
is unreachable. `origin` is `https://bench.invalid/github.com/<org>/<repo>` (in scope for the hooks,
unresolvable, no push URL). The session starts in the task's `cwd` with the repo root added, in
`bypassPermissions` mode, with the OS sandbox confining Bash writes and the network and
`tools/write-guard.mjs` confining the file tools to the repo and a per-task scratch directory. The
record's `diff` is from `base` to every tip the session left (the working tree on HEAD plus each local
branch not contained in another) and `commits` holds their messages; the diff is judged, not built.

Group (c) needs one clone per repo under `clones/` (or `--clones`), named as the task's `repo`; a
missing one fails with the `git clone` command to run. `node tools/task-repo.mjs --check` rebuilds every
task repo and checks that isolation.

## Run

Paths below are from the repo root. Without `--plugin`, the plugin under test is this checkout's
`xwiki/`. To measure another version, extract it — `git archive <sha> xwiki | tar -x -C <dir>` — and
pass `--plugin <dir>/xwiki`.

```
node eval/tools/recall.mjs --label master                          # retrieval recall, no LLM, seconds
node eval/tools/run.mjs    --label master --questions a,b,d         # sessions (resumable)
node eval/tools/run.mjs    --label master --questions c             # tasks (needs the clones)
node eval/tools/judge.mjs  --label master --questions a,b,c,d       # grades, then prints the scoreboard
node eval/tools/grade-det.mjs --labels master                      # mechanical group (c) verdicts
```

`--questions` takes group names or file paths; `--only a01,c07` narrows a run. `run.mjs` and `judge.mjs`
skip ids already done or graded, so an interrupted run resumes. Compare two labels by their
`_scoreboard.json`, and run each side several times before trusting a small difference: sessions are
not deterministic.

These questions have been seen by the sessions that tuned the KB, so a gain on them can be overfit. To
confirm a change to the retrieval mechanics, measure it on a fresh batch generated from recently merged
pull requests.

## Metrics

- `score` 0–3 by the Opus judge against the reference (3 = complete and correct); `full` = count of 3s;
  `harmful` = asserted a rule contradicting the reference. A group (c) point counts only when `covered`.
- `gold_file_read` (group a): the session read the gold KB file.
- `gold_in_pointers` / `gold_file_in_pointers` (group a): the prompt hook pointed at the gold section /
  file; `pointed`: share of sessions given any pointer (for group d, the lower the better).
- `okf_used`: share of sessions that touched the KB or loaded a skill.
- `in_tokens`: input tokens summed over all turns (cache reads included); `cost_usd` as reported.
- `recall.mjs`: kb-search's recall@1/3/5 of the gold file and the gold section on the raw question,
  with the misses and their top 3.
- `grade-det.mjs`: per group (c) point, the mechanical verdict next to the judge's; `exact: false`
  marks a point the grader checks only in part.
